Lege klasse

Doel: een lege klasse aanmaken en instanties uit maken.

Theorie

Een klasse is een blauwdruk voor objecten. Je maakt het aan met class: 

// een lege klasse — geen properties, geen constructors
public class Auto
{
}

Daarna kan je zoveel instanties maken als je wil met new: 

// instanties aanmaken
Auto mijnFord = new Auto();
Auto mijnKever = new Auto();
Auto autoX = new Auto();
...

Je kan de klasse en de instanties die je eruit maakt gebruiken zoals elk gegevenstype en variabelen, zoals in lijsten of methodes:

// gebruik in een methode
public static void (Auto a) {
   ...
}

// gebruik in een List
List<Auto> wagenpark = new List<Auto>() { mijnFord, mijnKever, autoX };
Console.WriteLine($"Aantal auto's: {wagenpark.Count}"); // 5

Properties

Doel: gebruik van properties in een klasse; standaardwaarden; object initializer syntax.

Theorie

Properties zijn (meestal) publiek beschikbare eigenschappen van een object. Voorlopig beperken we ons tot properties die je vrij kan lezen en schrijven met { get; set; }; dit noemt men automatische properties. 

public class Auto
{
    public string Merk { get; set; }
    public int Bouwjaar { get; set; }
    public bool IsElektrisch { get; set; } = false;  // standaardwaarde
    public List<string> Opties { get; set; } = new List<string>(); // standaard lege lijst
}

Properties instellen kan op twee manieren. De eerste manier is door ze één voor één in te stellen na het aanmaken van het object:

Auto a1 = new Auto();
a1.Merk = "Toyota";
a1.Bouwjaar = 2021;
a1.IsElektrisch = true;
a1.Opties = new List<string> { "Autopilot", "Panoramadak" };

Of compacter met de object initializer syntax (alles in één stap):

Auto a1 = new Auto
{
    Merk = "Toyota",
    Bouwjaar = 2021,
    IsElektrisch = true,
    Opties = new List<string> { "Autopilot", "Panoramadak" }
};

Validatie & methodes

Doel: niet-automatische properties met validatie; berekende properties; methodes.

Theorie

Er zijn twee redenen om de getter en/of setter van een property zelf te implementeren (niet-automatische property):

  • validatie: controleer de binnenkomende waarde (value) voor je het opslaat (in field)
  • berekende property: geeft enkel een waarde terug, geen setter nodig
public class BankRekening
{
    public string HouderNaam { get; set; }
    public DateOnly AangemaaktOp { get; set; } = DateOnly.Now;

    // property met validatie
    public decimal Saldo
    {
        get;
        set
        {
            // value: ingestelde waarde, field: opgeslagen waarde
            if (value < 0) throw new ArgumentException("saldo kan niet negatief zijn");
            field = value; 
        }
    }

    // berekende property: enkel getter nodig
    public int AantalJarenOpen
    {
        get { return DateOnly.FromDateTime(DateTime.Today).Year - AangemaaktOp.Year; }
    }

    // methode met validatie
    public void Afhalen(decimal bedrag)
    {
        if (bedrag <= 0) throw new ArgumentException("bedrag moet positief zijn");
        if (saldo - bedrag <= 0) throw new ArgumentException("saldo mag niet negatief worden");
        Saldo -= bedrag;
    }
}

Validatie in de setter gooit een ArgumentException bij een ongeldige waarde:

BankRekening r = new BankRekening { HouderNaam = "Lena", Saldo = 600 };
r.Afhalen(250);
Console.WriteLine(r.Saldo); // 350

r.Saldo = -100; // gooit ArgumentException: "saldo kan niet negatief zijn"
r.Afhalen(1000); // gooit ArgumentException: "saldo mag niet negatief worden"

ToString()

Doel: de methode ToString() overschrijven voor een mooie tekstweergave van een object.

Theorie

Elke klasse in C# erft impliciet over van object, en dus ook de methode ToString(). Standaard geeft die de typenaam terug, maar je kan ze overschrijven met override voor een zinvolle tekstweergave. 

public class Film
{
    public string Titel { get; set; }
    public int Jaar { get; set; }
    public double Score { get; set; }

    public override string ToString()
    {
        return $"{Titel} ({Jaar}) — ★ {Score:F1}";
    }
}

In een string context als Console.WriteLine() en string interpolatie wordt automatisch ToString() aangeroepen:

Film f = new Film { Titel = "Inception", Jaar = 2010, Score = 8.8 };

Console.WriteLine(f);            // Inception (2010) — ★ 8.8
Console.WriteLine($"Film: {f}"); // Film: Inception (2010) — ★ 8.8

Compositie

Doel: compositie — een klasse gebruiken als type van een property in een andere klasse.

Theorie

Bij compositie gebruik je een klasse als type van een property in een andere klasse. Zo bouw je complexe objecten op uit eenvoudigere bouwstenen ("heeft een"-relatie). 

public class Speler
{
    public string Naam { get; set; }
    public int Rugnummer { get; set; }
    public override string ToString() => $"#{Rugnummer} {Naam}";
}

public class Team
{
    public string Naam { get; set; }
    public string Stad { get; set; }
    public List<Speler> Spelers { get; set; } = new List<Speler>(); // compositie: gebruik klasse Speler in klasse Team
    public int AantalSpelers => Spelers.Count;
}

Gebruik:

Team t = new Team { Naam = "FC Demo", Stad = "Gent" };
t.Spelers.Add(new Speler { Naam = "Ali Bouazza", Rugnummer = 9 }); // voeg Speler toe aan Team
t.Spelers.Add(new Speler { Naam = "Nora Claes", Rugnummer = 7 }); // voeg Speler toe aan Team

Console.WriteLine($"{t.Naam} heeft {t.AantalSpelers} spelers:");
foreach (Speler s in t.Spelers)
{
   Console.WriteLine($"  {s}"); 
}

Constructors

Doel: constructors met parameters; constructor chaining met :this().

Theorie

Met een constructor geef je aan hoe een object kan aangemaakt worden uit de klasse. Je kan meerdere constructors voorzien met verschillende parameters. Met :this() roep je een andere constructor van dezelfde klasse op (constructor chaining), zodat je code niet herhaalt. 

public class Adres
{
    public string Straat { get; set; }
    public int Huisnummer { get; set; }
    public string Gemeente { get; set; }
    public string Land { get; set; } = "België";

    // constructor met verplichte velden
    public Adres(string straat, int huisnummer, string gemeente)
    {
        Straat = straat;
        Huisnummer = huisnummer;
        Gemeente = gemeente;
    }

    // uitgebreide constructor — hergebruikt de eerste via :this()
    public Adres(string straat, int huisnummer, string gemeente, string land)
        : this(straat, huisnummer, gemeente) // roep eerst de vorige constructor op
    {
        Land = land; // stel dan dit in
    }

    public override string ToString() => $"{Straat} {Huisnummer}, {Gemeente} ({Land})";
}

Gebruik van de twee constructors:

Adres a1 = new Adres("Kerkstraat", 12, "Aalst"); // constructor 1
Console.WriteLine(a1); // Kerkstraat 12, Aalst (België)

Adres a2 = new Adres("Rue Neuve", 5, "Bruxelles", "France"); // constructor 2
Console.WriteLine(a2); // Rue Neuve 5, Bruxelles (France)
